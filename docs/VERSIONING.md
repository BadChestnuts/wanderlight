# 正式版与开发版

当前正式网站：https://badchestnuts.github.io/wanderlight/ 。原有 Sites 网站也保持原部署。

| 分支 | 用途 |
| --- | --- |
| `main` | 正式网站的源码；推送会触发 GitHub Pages 发布 |
| `stable-v1.0.0` | 保留 2026-10-09 的完整版本，指向 `d4e90ff37112d1524eb3cea147ccf3f10438fa44` |
| `develop` | 尝试新功能，运行验证，不发布正式网站 |
| `feature/功能名称` | 从开发版出发，单独试验一项功能 |

## 开发和试用

1. 在 `develop` 或从它建立的功能分支中修改。
2. 用 `npm run dev` 启动本地开发预览，地址为 http://localhost:4176/ 。此地址仅在本机服务器运行时可访问。
3. 按修改范围运行现有测试和静态检查。开发分支的 GitHub Actions 也会运行 `node --test tests/travel.test.mjs` 与 `node scripts/verify.mjs`。
4. 在线预览应另建托管项目，使用不同的域名；同一个 GitHub Pages 仓库的发布会替换正式网站，不能作为开发版预览。

开发分支的 `pages.yml` 为发布任务增加了仅允许 `main` 的条件，所以从开发分支手动运行这个工作流也会跳过正式发布。当前 `main` 的源码和部署设置保持原样；这里没有启用 GitHub 分支保护规则，操作时仍需遵守上述分支约定。

## 决定升级时

先给用户提供可试用的版本、改动说明和验证结果。用户明确决定升级后，保存升级前的源码基线和用户的完整旅行数据备份，再将已验证的开发改动合并到 `main`，检查正式发布结果。

如果用户希望一直保留 v1.0.0 的现有网址，可以将升级版放在另一个仓库或托管项目，长期保留两个网站。

## 放弃试验或恢复旧版本

尚未发布的试验只需在开发分支中撤回相应提交，或从基线建立新的试验分支。正式发布后的恢复应先从已保存的旧提交建立恢复分支，测试后通过一次新发布恢复，不使用强制推送覆盖历史。

恢复旧代码前，需要确认较新版本是否改变过数据格式；代码回退本身不会回退浏览器数据。涉及数据变更时，先备份，再在隔离的预览地址中验证。

## 旅行记录和照片

数据保存于每个浏览器、每个网站来源的本地存储。正式网站、本地开发预览和另一个在线预览域名的数据互不自动同步。只换 URL 路径通常仍共用一个来源，不能依赖路径隔离数据。

源码分支和 ZIP 不含你在浏览器中录入的旅行数据。在“数据设置”中导出完整备份，需要时手动导入。不要把自己的记录备份、照片或密钥上传到公开仓库。
